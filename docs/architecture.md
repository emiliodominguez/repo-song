# Architecture

```
git history ──► seed ──► composer ──► notes per part ──► renderer ──► mastered PCM ──► 24-bit WAV
 (history.ts)          (compose/lofi.ts)                 (render/lofi.ts)              (audio/wav.ts)
                                                              ▲
                                     recordings (assets.ts → instruments/vcsl.ts)
```

## Modules

| Path                         | Role                                                                                                                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/cli.ts`                 | Argument parsing, progress lines (stderr), error reporting. All text comes from `src/i18n`.                                                                                                                        |
| `src/history.ts`             | Finds the repository top level, root commit and commit count via `git`.                                                                                                                                            |
| `src/compose/rng.ts`         | Seeded RNG (FNV-1a + Mulberry32), identical to music-radio's.                                                                                                                                                      |
| `src/compose/theory.ts`      | Scales and scale-degree arithmetic.                                                                                                                                                                                |
| `src/compose/lofi.ts`        | The composer: key/mode/tempo, chords, Rhodes comping, bass, melody, drums. Output: `Song` with notes in seconds.                                                                                                   |
| `src/instruments/catalog.ts` | Which VCSL files each sampled instrument uses, and the pinned VCSL commit.                                                                                                                                         |
| `src/instruments/vcsl.ts`    | Loads recordings into sampler instruments (zones by note, velocity layer, round robin).                                                                                                                            |
| `src/instruments/sampler.ts` | Offline multisample playback: nearest root, layer crossfade, Hermite resampling, damper and release samples.                                                                                                       |
| `src/instruments/synths.ts`  | Modelled Rhodes, bass, kick, pad.                                                                                                                                                                                  |
| `src/dsp/*`                  | Filters (RBJ biquads), dynamics (compressor, sidechain, limiter, gated RMS), character (saturation, tape, vinyl, crunch, tremolo), reverb (FFT convolution, generated room IR), tone (band analysis, matching EQ). |
| `src/render/lofi.ts`         | Renders each part, levels and sums them, adds the shared room, masters.                                                                                                                                            |
| `src/assets.ts`              | Cache location, manifest check, resumable parallel download from the pinned VCSL commit.                                                                                                                           |
| `src/assets-manifest.json`   | Generated by `pnpm assets:manifest`: every recording used, with its size.                                                                                                                                          |

## The determinism contract

A repo's song must not change between runs or machines, or the "this is what my repo sounds like" idea falls apart. Three things guarantee it:

1. **The seed** is the root commit (`git rev-list --max-parents=0 HEAD`, first line).
2. **RNG draw order is part of the sound.** The composer and renderer each draw from their own seeded stream (`lofi:<seed>`, `render:<seed>`, `room:<seed>`, `vinyl:<seed>`). Adding, removing or reordering a draw changes every song. The composer even burns eight draws where music-radio chose GM programs, to stay seed-compatible with it.
3. **The recordings are pinned** to one VCSL commit, and the manifest records each file's size.

Two tests pin this down: `tests/unit/compose.test.ts` hashes a composed song, and `tests/unit/render.test.ts` hashes the rendered PCM. If either changes, it must be on purpose; listen before re-pinning. `Math.sin`/`exp`/`tanh` are deterministic within a V8 version, so a Node upgrade can legitimately move the render hash.

## Performance

Rendering is single-threaded and allocation-light; a 45 s song takes about 7 s on an M-series Mac. The biggest costs are the per-sample synth loops (Rhodes, bass), the convolution (block FFT, 65 536-sample blocks) and the three matching-EQ measurement passes (ten band filters each).

## Conventions

TypeScript run directly by Node (type stripping) in development and compiled by `tsc` for publishing. Function declarations, tabs, 150 columns, JSDoc on every function, conventional commits; see `AGENTS.md`. `noUncheckedIndexedAccess` is off on purpose: DSP code indexes typed arrays in every inner loop.
